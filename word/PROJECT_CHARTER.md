## 一、项目立项说明

### 1.1 核心定义

1. **项目名称**：记忆学习平台（Memory Learning Platform）
2. **一句话定义**：一个融合「笔记管理」与「间隔重复记忆」的个人学习工具，帮助用户把零散知识转化为可系统复习的记忆卡片，通过科学的复习节奏将短期记忆固化为长期记忆。
3. **产品形态**：本地运行的单用户 Web 应用（前端浏览器访问 + 后端本地服务 + 本地数据库）。

### 1.2 目标受众

| 受众 | 场景 | 核心诉求 |
|------|------|---------|
| **学生（考试备考）** | 准备期末考试、考研、资格考试（如法考/CPA/医师资格） | 大量知识点需要反复记忆；需要按考试日期倒排复习计划 |
| **语言学习者** | 背单词、语法点、常用表达 | 碎片时间每日复习；需要易上手、低摩擦的建卡体验 |
| **知识工作者** | 阅读专业书籍/论文后整理笔记 | 笔记与记忆卡片割裂，学完就忘；希望笔记直接转化为复习材料 |
| **终身学习者** | 跨领域自学（编程、历史、医学常识等） | 需要可视化学习数据反馈，维持学习动力 |

### 1.3 要解决的痛点

1. **笔记与记忆脱节**
   - **现状**：记了大量笔记，但笔记躺在文档里从不复习，知识留存率低（艾宾浩斯遗忘曲线：24 小时后仅剩约 33%）
   - **解法**：笔记可一键转换为记忆卡片，打通「记录 → 复习」链路

2. **复习节奏无章法**
   - **现状**：手动决定「今天复习什么」既不科学也不持续，要么遗忘复习、要么低效重复已掌握内容
   - **解法**：内置间隔重复算法（简化 SM-2），系统自动安排每日复习队列，只需自评掌握程度

3. **现有工具门槛高**
   - **现状**：Anki 桌面版界面陈旧、学习曲线陡峭；市面新工具多为订阅制，价格高且数据在云端
   - **解法**：轻量级本地应用，零学习成本上手；数据完全本地存储，无隐私顾虑、无订阅费

4. **学习反馈缺失**
   - **现状**：不知道自己学了多少、记住多少、坚持了多久，缺少正向激励
   - **解法**：日历热力图 + 统计面板 + 连续学习天数，用可视化数据形成正向反馈循环

5. **建卡成本高**
   - **现状**：手敲卡片耗时费力，从零整理知识点需要大量重复劳动
   - **解法**：模板批量建卡、笔记转换建卡、JSON 批量导入，降低建卡摩擦

### 1.4 第一版（V1）核心目标

#### 1.4.1 术语说明

> **术语说明**：「第一版（V1）」指第一版全周期，由两个里程碑组成 —— **V1.0 (MVP)** 和 **M1**（里程碑定义见第四章）。以下分级目标中，P0 项在 V1.0 (MVP) 交付；P1/P2 项在 M1 交付。

#### 1.4.2 V1 定位

V1 定位：**跑通「建卡 → 复习 → 统计」最小闭环**，验证核心价值。

#### 1.4.3 目标分级

**P0 核心目标（V1.0 MVP 交付，4 项）**

1. **牌组管理**：创建/编辑/删除牌组，卡片式网格展示
2. **卡片管理**：手动创建（Markdown 正反面）、编辑、删除卡片
3. **复习模式**：Q&A 卡片交互，4 级自评（完全忘记/困难/正确/简单），SM-2 间隔调度
4. **基础统计**：总卡片数/待复习数/正确率/连续学习天数数据面板

**P1 重要目标（M1 交付，4 项）**

1. **笔记系统**：文件夹管理、今日临时笔记、富文本编辑、笔记转卡片
2. **统计可视化**：日历热力图、时间轴
3. **模板系统**：预置 3 套模板 + 自定义模板
4. **数据迁移**：JSON 导入/导出（单牌组/全量）

**P2 增强目标（M1 交付，3 项）**

1. **考试目标**：考试日期设定、每日复习量目标
2. **全局搜索**：跨牌组/笔记的关键词搜索
3. **附件上传**：图片/PDF/文本/Word 上传并关联笔记

#### 1.4.4 V1 明确不做

1. 不做 AI 生成卡片 / AI 问答 / PDF 智能解析（里程碑 M2）
2. 不做用户注册/登录/多用户体系（里程碑 M2，仅预留权限插槽）
3. 不做 .apkg 二进制格式导入（仅 JSON）
4. 不做移动端适配（里程碑 M3）

### 1.5 V1 验收规则

#### 1.5.1 功能验收（必须全部通过）

1. **创建牌组**：输入名称 → 创建成功 → 出现在牌组网格中
2. **添加卡片**：在牌组内添加正面+背面内容 → 保存后列表可见
3. **Markdown 渲染**：卡片包含标题/代码块/列表 → 复习时渲染正确
4. **进入复习**：牌组有到期卡片 → 复习队列按到期时间排序展示
5. **4 级自评**：点击任一评分按钮 → 卡片状态更新 → 下一张卡片出现
6. **间隔生效**：「完全忘记」的卡片 10 分钟后再次到期；「简单」的卡片间隔显著变长
7. **复习记录**：每次评分写入复习记录 → 统计面板数据随之更新
8. **笔记转卡片**：创建含标题段落的笔记 → 一键转换 → 生成对应卡片
9. **导出导入**：导出牌组 JSON → 删除该牌组 → 导入 JSON → 牌组和卡片完整恢复（含 SM-2 状态）
10. **数据持久化**：重启应用 → 所有数据完整保留

#### 1.5.2 技术验收（必须全部通过）

1. **启动**：`npm run dev` 一键启动，前端 5173 + 后端 3000，健康检查返回正常
2. **接口规范**：全部端点响应结构为 `{code, message, data}`；错误码符合注册表
3. **分层纪律**：无跨层引用；routes 无业务逻辑；repositories 无业务判断
4. **数据库规范**：WAL + 外键约束开启；全部查询参数化；无字符串拼接 SQL
5. **日志**：每个请求有日志；异常写 error.log；无 console.log 残留
6. **类型安全**：`tsc --noEmit` 前后端均零错误
7. **构建**：前后端 `npm run build` 均成功

## 二、产品流程和业务路径

### 2.1 核心用户旅程

```
┌─────────────────────────────────────────────────────────────┐
│                    用户首次使用                                 │
│  打开应用 → 创建第一个牌组 → 添加第一张卡片 → 立即复习            │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    日常使用循环（每日）                          │
│                                                               │
│  ① 打开应用（首页显示今日待复习数）                              │
│        │                                                      │
│  ② 进入牌组 → 开始复习                                         │
│        │                                                      │
│  ③ 逐张卡片：看问题 → 回忆 → 显示答案 → 4 级自评                │
│        │                                                      │
│  ④ 复习完成 → 查看统计面板（今日完成数/正确率/连续天数）          │
│        │                                                      │
│  ⑤ (可选) 新建卡片 / 记笔记 / 笔记转卡片                        │
│        │                                                      │
│  ⑥ 次日重复 ①                                                │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 五大业务路径

#### 2.2.1 路径 A：手动建卡路径

**操作步骤**

1. 首页 → 记忆卡片 → 牌组列表 → 进入牌组
2. 点击 [+新建卡片]
3. 输入正面（Markdown）
4. 输入背面（Markdown）
5. （可选）选择模板
6. 保存 → 卡片立即进入复习队列（新卡默认到期）

**涉及对象**：Deck → Card

**关键规则**：

- 新卡片 `interval=0, ease_factor=2.5, next_review=now`，创建即可复习

#### 2.2.2 路径 B：笔记转卡路径

**操作步骤**

1. 首页 → 文档与文件夹 → 新建/打开笔记
2. 富文本编辑 → 保存
3. 点击 [转为记忆卡片] → 选择目标牌组
4. 系统解析笔记结构生成卡片
5. 预览确认 → 批量写入 → 在牌组中可见

**涉及对象**：Folder → Note → Card（source_note 关联）

**关键规则**：

- 转换生成的卡片 `source_note` 回指笔记，支持追溯
- 转换是追加操作，不修改原笔记

#### 2.2.3 路径 C：复习路径

**操作步骤**

1. 首页（今日待复习 N 张）→ 选择牌组 → 复习模式
2. 系统查询到期卡片：`next_review <= now`
3. 按到期时间升序逐张展示
4. 每张卡片：展示正面 → 用户回忆 → 点击 [显示答案] → 4 级自评
5. SM-2 算法计算下次复习时间 → 更新卡片状态 + 写入复习记录（同一事务）
6. 队列耗尽 → 显示本次复习总结

**涉及对象**：Card → ReviewLog

**关键规则**：

- 评分与状态更新的映射：forgot→10分钟 / hard→1天 / good→×ease_factor / easy→×ease_factor×1.3（新卡首次复习不套用公式，按 §3.3 基线设置）
- 卡片状态更新与复习记录写入必须原子性（事务）
- 复习队列为空时给出明确提示

#### 2.2.4 路径 D：统计回顾路径

**操作步骤**

1. 首页 → 卡片统计
2. 数据面板：总卡片/已掌握/待复习/今日待复习/正确率/连续学习天数
3. 日历热力图：按月展示每日复习量，颜色深浅表示密度
4. 时间轴：倒序展示复习记录和卡片创建记录

**涉及对象**：Card + ReviewLog（聚合查询）

**关键规则**：

- 统计口径 — 正确率 = (good + easy) / 总评分次数
- 连续学习天数 = 从今天倒推连续有复习记录的天数

#### 2.2.5 路径 E：数据迁移路径

**操作步骤**

1. 设置/牌组页 → 导出
2. 单牌组导出：牌组信息 + 全部卡片（含 SM-2 状态）+ 复习记录
3. 全量导出：全部牌组 + 笔记 + 模板
4. 生成 JSON 文件下载
5. 导入（新环境/恢复数据）：上传 JSON → 结构校验 → 事务内批量写入
6. 同名牌组策略：追加卡片不覆盖 → 返回导入摘要

**涉及对象**：Deck + Card + Note + Template（序列化）

**关键规则**：

- 导入全流程事务化，任一失败全量回滚

### 2.3 业务规则汇总

#### 2.3.1 复习调度规则（R1-R4）

- **R1**｜新卡片创建后立即到期（`next_review = now`）—— 影响范围：建卡 → 复习无等待
- **R2**｜到期判定：`next_review <= datetime('now')` —— 影响范围：复习队列筛选
- **R3**｜评分 4 级，SM-2 状态机驱动间隔调度 —— 影响范围：复习 → 状态更新
- **R4**｜ease_factor 下限 1.3，interval 上限 365 天 —— 影响范围：算法边界

#### 2.3.2 数据一致性规则（R5-R9）

- **R5**｜删除牌组级联删除卡片和复习记录（考试目标保留，其 deck_id 置 NULL）—— 影响范围：数据一致性
- **R6**｜删除笔记级联删除附件（记录 + 物理文件）—— 影响范围：数据一致性
- **R7**｜文件夹非空禁止删除 —— 影响范围：防止孤儿数据
- **R8**｜系统预置模板（is_default=1）不可删除 —— 影响范围：模板可用性
- **R9**｜复习状态更新与记录写入同一事务 —— 影响范围：数据一致性

#### 2.3.3 数据迁移与统计口径（R10-R11）

- **R10**｜导入数据同名牌组追加卡片，不覆盖元信息 —— 影响范围：数据迁移幂等
- **R11**｜「已掌握」统计口径：`repetitions >= 3` 且 `interval >= 21 天`（interval 以分钟存储，即 >= 30240 分钟）—— 影响范围：统计面板 / 全局概览

## 三、核心业务对象

### 3.1 对象总览与关系

```
Folder (文件夹) ──1:N── Note (笔记) ──1:N── Attachment (附件)
     │                    │
     │1:N                 │0:1 (source_note)
     │                    ▼
     └──1:N── Deck (牌组) ──1:N── Card (卡片) ──1:N── ReviewLog (复习记录)
                                      ▲
                                      │ N:1 (deck_id)
                              Exam (考试目标) ──1:N── 目标关联
                                        │
Template (模板) — 独立对象，建卡时引用
```

### 3.2 对象定义

#### 3.2.1 Folder — 文件夹

- **核心属性**：name, parent_id
- **生命周期**：创建 → 重命名 → 删除（空文件夹）
- **关键行为**：组织笔记和牌组；树形嵌套

#### 3.2.2 Note — 笔记

- **核心属性**：title, content (富文本JSON), is_today, tags, folder_id
- **生命周期**：创建 → 编辑 → 迁移文件夹 → 转卡片 → 删除
- **关键行为**：今日临时笔记可转为永久笔记；一键转为卡片

#### 3.2.3 Attachment — 附件

- **核心属性**：filename, filepath, file_type, file_size
- **生命周期**：上传 → 关联笔记 → 随笔记删除
- **关键行为**：图片/PDF 上传，供笔记引用

#### 3.2.4 Deck — 牌组

- **核心属性**：name, description, icon, color, folder_id
- **生命周期**：创建 → 编辑 → 复习使用 → 删除（级联）
- **关键行为**：卡片集合容器；复习入口

#### 3.2.5 Card — 记忆卡片

- **核心属性**：front (问题), back (答案), tags, source_note, **SM-2 状态** (ease_factor/interval/repetitions/next_review/last_reviewed)
- **生命周期**：创建（新卡立即到期）→ 反复复习（状态机演化）→ 删除
- **关键行为**：核心对象；SM-2 状态机驱动其复习调度

#### 3.2.6 ReviewLog — 复习记录

- **核心属性**：card_id, deck_id, result, reviewed_at
- **生命周期**：追加写入，永不修改
- **关键行为**：统计/日历/时间轴的数据源

#### 3.2.7 Template — 模板

- **核心属性**：name, front, back, is_default
- **生命周期**：预置（迁移插入）→ 用户自定义 → 删除（默认模板除外）
- **关键行为**：建卡时填充预设结构

#### 3.2.8 Exam — 考试目标

- **核心属性**：name, deck_id, target_date, target_count, status
- **生命周期**：创建 → 活跃 → 完成/过期
- **关键行为**：设定考试日期和每日复习量目标

### 3.3 核心对象：Card 的状态机

```
                    ┌────────────────────────────┐
                    │  新卡 (interval=0,          │
                    │  repetitions=0,            │
                    │  ease_factor=2.5,          │
                    │  next_review=now)          │
                    └──────────┬─────────────────┘
                               │ 用户复习 + 4级自评
                               ▼
              ┌──────────────────────────────────┐
              │            评分分叉               │
              ├──────────────────────────────────┤
              │ forgot → repetitions=0,           │
              │          interval=10分钟,         │
              │          ease_factor -= 0.2       │
              │                                   │
              │ hard   → repetitions=0,           │
              │          interval=1天,            │
              │          ease_factor -= 0.15      │
              │                                   │
              │ good   → repetitions+1,           │
              │          interval × ease_factor,  │
              │          ease_factor 不变         │
              │                                   │
              │ easy   → repetitions+1,           │
              │          interval × ease_factor   │
              │                   × 1.3,          │
              │          ease_factor += 0.15      │
              └──────────────┬───────────────────┘
                             │ 更新 next_review = now + interval
                             ▼
                    ┌────────────────────────────┐
                    │  等待到期 → 再次进入复习队列  │
                    └────────────────────────────┘
```

> **首次复习基线**：新卡（interval=0）首次评分不套用 × ease_factor 公式 —— good → interval = 1 天（1440 分钟）、easy → interval = 4 天（5760 分钟）；forgot / hard 按状态机执行（10 分钟 / 1 天）。

## 四、后期项目规划和里程碑

### 4.1 里程碑总览

```
V1.0 (MVP)          M1 核心闭环          M2 AI 增强          M3 移动与协作
───────────       ─────────────       ─────────────       ─────────────
2026.06           2026.06-07          2026.08-09          2026.10+

建卡→复习→统计     数据完善+体验打磨     AI 全链路          多端多用户
```

| 里程碑 | 时间窗口 | 主题 | 核心交付物 |
|--------|---------|------|-----------|
| **V1.0 (MVP)** | 2026-06 | 核心闭环 | 牌组/卡片 CRUD、复习模式、数据面板、JSON 导入导出 |
| **M1** | 2026-06 ~ 07 | 体验完善 | 笔记系统（文件夹/今日笔记/富文本/转卡片）、日历热力图、时间轴、模板系统、考试目标、附件上传、全局搜索 |
| **M2** | 2026-08 ~ 09 | AI 增强 | AI 生成卡片、AI 问答、PDF 智能解析、AI 导师、用户体系（注册/登录/多用户） |
| **M3** | 2026-10+ | 多端协作 | 移动端适配（PWA 或响应式）、好友邀请、牌组分享、数据云同步 |

### 4.2 各里程碑详细规划

### 4.3 风险与应对

| 风险 | 影响 | 概率 | 应对 |
|------|------|------|------|
| 复习算法调优不当导致体验差 | 用户放弃使用 | 中 | SM-2 参数（ease_factor 步长、interval 系数）设计为配置化，M1 阶段根据真实使用数据调整 |
| 富文本编辑器集成复杂度超预期 | M1 延期 | 低 | Tiptap 采用最小配置起步（标题/列表/表格），复杂功能按需扩展 |
| 本地 SQLite 数据丢失 | 用户数据全灭 | 低 | M1 加入自动备份（每日快照保留 7 天）；JSON 导出作为兜底 |

### 4.4 成功度量指标

| 指标 | 定义 | 目标值 (M1 末) |
|------|------|---------------|
| 日活复习用户 | 当日至少完成 1 次复习的活跃使用 | 持续使用（个人项目，观察趋势） |
| 卡片创建效率 | 平均创建一张卡片耗时 | ≤ 30 秒（手动）/ ≤ 5 秒（模板） |
| 复习完成率 | 进入复习队列后完成的卡片占比 | ≥ 80% |
| 笔记转卡转化率 | 转为卡片的笔记占总笔记比例 | ≥ 30% |
| 数据留存 | 使用 30 天后的数据完整率 | 100%（本地存储） |
